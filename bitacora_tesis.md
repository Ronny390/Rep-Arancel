- **Estado:** ✅ Completada
- **Actividades realizadas:**
  - Estructuración y corrección del modelo Entidad-Relación (ER) adaptado a la jerarquía arancelaria de Venezuela.
  - Definición de llaves primarias, foráneas y jerarquía: Sección ➔ Capítulo ➔ Partida ➔ Subpartida.
  - Decisiones de diseño técnico aplicadas:

    - Manejo de subpartidas a 10 dígitos (desagregación nacional) identificando líneas terminales (liquidables) versus líneas de agrupación.
    - **Relación reflexiva `fk_subpartida_padre`:** Permite identificar sin ambigüedad las descripciones "Los demás", trazando el árbol jerárquico de cada subpartida hasta su raíz.
  - Generación del diagrama visual de la arquitectura.

## Fase III: Desarrollo de la Estructura de Base de Datos (Semanas 7 - 9)
- **Estado:** ✅ DDL + DML Completados
- **Actividades realizadas:**
  - Codificación del script DDL completo para Oracle (`sql/arancel_venezuela_oracle_ddl.sql`).
  - Se crearon **9 tablas + 1 vista** con sus constraints, índices y comentarios:
    1. `UNIDAD_FISICA` — Catálogo de unidades (kg, u, l, m, t, kW, kWh, mg, mm).
    2. `SECCION` — 22 secciones (romano I al XXII).
    3. `CAPITULO` — 98 capítulos (código 2 dígitos).
    4. `PARTIDA` — 1,275 partidas (código 4 dígitos).
    5. `SUBPARTIDA` — 9,725 subpartidas hasta 10 dígitos. Campo `es_terminal` (7,206 terminales con tarifa). **Relación reflexiva `fk_subpartida_padre`** para resolver "Los demás".
    6. `TARIFA_AD_VALOREM` — 7,206 tarifas AEC/ExAEC (separadas para historial de Gaceta Oficial).
    7. `REGIMEN_LEGAL` — 21 regímenes de importación/exportación.
    8. `SUBPARTIDA_REGIMEN` — 3,018 relaciones N:M subpartida ↔ régimen.
    9. `NOTA_LEGAL` — 105 notas legales multinivel con 4 FKs opcionales y CHECK constraint.
    - **Vista:** `V_SUBPARTIDA_DESC_COMPLETA` con `SYS_CONNECT_BY_PATH` para uso en Metabase.
  - **Decisión de diseño clave — Relación reflexiva `fk_subpartida_padre`:**
    - Resuelve el problema de los textos ambiguos "Los demás" en la base de datos.
    - El código numérico único de cada subpartida (ej. `0306.16.10.90`) identifica de forma inequívoca de cuál "Los demás" se trata.
    - La Vista `V_SUBPARTIDA_DESC_COMPLETA` usa `SYS_CONNECT_BY_PATH` para concatenar el árbol completo: `Crustáceos > Congelados > Camarones... > Enteros > Los demás`, evitando la ambigüedad visual en Metabase.
  - **Solución en Metabase:** La vista jerárquica permite filtrar y mostrar la `descripcion_completa` en lugar del campo `descripcion` corto, con el nivel de profundidad (`nivel_jerarquico`) disponible para filtros.
  - Se aplicaron buenas prácticas Oracle:
    - `NUMBER GENERATED BY DEFAULT AS IDENTITY` para PKs.
    - `CLOB` para texto largo.
    - `ON DELETE CASCADE` en FKs de la cadena jerárquica.
    - `CHECK` constraints para validar integridad.
    - Índices en todas las FKs para optimizar JOINs.
    - `COMMENT ON TABLE / COLUMN` para autodocumentación.
  - **9 archivos DML generados** en `sql/` — Orden de ejecución en Oracle:
    1. `dml_01_unidad_fisica.sql` — 9 unidades únicas
    2. `dml_02_regimen_legal.sql` — 21 regímenes
    3. `dml_05_seccion.sql` — 22 secciones
    4. `dml_06_capitulo.sql` — 98 capítulos
    5. `dml_07_partida.sql` — 1,275 partidas
    6. `dml_08_subpartida.sql` — 9,725 subpartidas (con `fk_subpartida_padre` y `es_terminal`)
    7. `dml_03_tarifa_ad_valorem.sql` — 7,206 tarifas
    8. `dml_04_subpartida_regimen.sql` — 3,018 relaciones N:M
    9. `dml_09_nota_legal.sql` — 105 notas legales
- **Actividades pendientes:**
